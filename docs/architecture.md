# Nuit Bot Architecture

This document defines the production-grade multi-stage LangGraph workflow used by the Nuit Fragrances Customer Service Chatbot.

## 2. State Definition (`AgentState`)

The graph state is a dictionary that tracks inputs, outputs, and intermediate evaluation metrics:

* **`messages`**: Accumulated conversation history (with `add_messages` reducer to automatically merge tool outputs).
* **`user_prompt`**: The latest message string sent by the user.
* **`is_safe`**: Boolean status indicating whether the query passed the Input Guardrail.
* **`emotion_signals`**: Structured details about the customer's sentiment (`vibe`, `intent`, and `reason`).
* **`enhanced_prompt`**: Enriched prompt injection payload including core instructions, permanent context, dynamic tools, and emotional indicators.
* **`response`**: Candidate text generated by the LLM responder.
* **`audit_logs`**: Log history of all audit evaluations.
* **`failed_checks`**: List of current rule violations to be corrected.
* **`iteration_count`**: Counter for the self-correction retry loop.

## 3. Node Workflows

### 1. Input Guardrail (`input_guardrail`)
An LLM-based classifier that checks if the customer's query is related to Nuit Fragrances (perfumes, home mists, orders, policies) and safe.
* **If UNSAFE**: Immediately overrides the response with the standard customer care phone intake block, short-circuiting the graph.
* **If SAFE**: Normal flow continues.

### 2. Emotion & Intent Analyzer (`analyze_emotion`)
Evaluates the user prompt and recent conversation history to identify frustration levels (anger, anxiety) and purchasing signals (information-seeking, purchase-ready). Saves these indicators as metadata signals.

### 3. Prompt Enhancer (`enhance_prompt`)
Combines Nuit's core persona system prompt, permanent context (brand guidelines and SOPs), dynamic tool instructions, and the user's emotional state into a comprehensive instructions payload for the generator.

### 4. Tool-Calling Generator (`generate`)
Uses a tool-calling execution loop to generate the candidate response. The model has access to the **`retrieve_document_content`** tool and can dynamically fetch the contents of registered files as needed before responding.

### 5. Audits & Output Guardrail (`run_audits`)
Runs four sequential checks on the generated candidate response:
1. **Brand Audit**: Validates guidelines (maximum 3 sentences, no emojis, bolding restricted to pricing/links).
2. **Fact Audit**: Validates pricing/shipping fees/policies against official facts.
3. **Emotional Audit**: Confirms the tone is appropriate for the user's emotional signals.
4. **Output Guardrail**: Ensures no prompt leaks or internal system metadata are exposed.

All violations are captured under `failed_checks`.

### 6. Iteration Enhancer (`iteration_enhancer`)
If any audit fails and we are under the maximum retry threshold (3 attempts), this node increments the `iteration_count` and passes the audit failure details back to the generator as revision feedback for self-correction.

## 4. Document Classification & Retrieval Tools

### Permanent Context (Always Preloaded)
* `brand_identity.md`: Brand voice guidelines and sensory identity parameters.
* `customer_service_sop.md`: Transaction procedures and handoff routes.

### Dynamic Context (Fetched as needed via `retrieve_document_content`)
The agent decides to load these files using their registered descriptions:
* **`faq`**: Handles delivery times, shipping costs, international transport, return windows.
* **`icp`**: Handles user demographic traits and career profiles (Segment Alpha, Beta, Gamma).
* **`meta_ad_strat`**: Handles ad campaigns, Shark Tank validation, and conversion bundle codes.
* **`product_specs`**: Handles olfactory classifications, ingredients, and notes breakdowns.
* **`terms_of_conditions_and_policies`**: Handles catalog variant specs, refund eligibility, and damage validation steps.
